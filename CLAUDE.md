# Notes vault

A personal, local notes vault: Claude writes notes from podcast/YouTube transcripts and conversations.
The owner reads them by double-clicking `index.html`; no server, database or framework.

Read claude-config/lessons.md at the start of each session.

## Layout

```
notes/
  index.html                 # the viewer
  viewer.js                  # viewer logic
  style.css                  # viewer styles
  vendor/marked.min.js       # vendored Markdown renderer, pinned version
  notes.js                   # GENERATED by build.py; committed, never hand-edited
  build.py                   # bundles vault/*.md -> notes.js
  vault/                     # one Markdown file per note (source of truth)
  sources/                   # raw transcripts as received; not bundled
  templates/note.md          # blank note template
  tests/                     # test_build.py (Python), viewer.test.js (Node)
  claude-config/             # lessons.md and task tracking
  docs/superpowers/          # specs and plans
  CLAUDE.md                  # this file
  README.md                  # project overview for humans
```

## Adding a note

1. Receive a link or pasted transcript. Save raw material to `sources/YYYY-MM-DD-<slug>.<ext>` when there is any. (`conversation` notes skip this step.)
2. Write `vault/YYYY-MM-DD-<slug>.md` from `templates/note.md`.
3. Run `python3 build.py`; fix any reported error.
4. Tell the owner the note is ready and what the top takeaways are.

## Note format rules

- File name: `vault/YYYY-MM-DD-slug.md`; the date is the day the note was written.
- Front matter is a `key: value` block between `---` lines.
- Required fields: `title`, `source`, `date`. Optional: `url`, `published`, `author`, `tags` (comma-separated, lowercase).
- Allowed `source` values: `podcast`, `youtube`, `conversation`.
- Everything before `## Full writeup` is the glance; everything from that heading on is the full writeup. Without the heading, the whole body is the glance.
- Keep the glance under ~150 words: one or two intro sentences, then `## Takeaways` with 5-10 standalone bullets. Concrete beats vague: numbers, names, rules of thumb.
- Full writeup: unbounded; `###` sections following the flow of the source. Notable quotes as blockquotes with a timestamp when known.
- `templates/note.md` holds plain placeholders only (no inline `# ...` comments; they would be parsed into values). Fill `title`, set `source`, `date` (the day the note was written, `YYYY-MM-DD`); `published` (when the source was published), `url`, `author` are optional and may be deleted if unused; `tags` is comma-separated and lowercase.
- Do not leave HTML comments in notes.

## Never

- Hand-edit `notes.js`; it is generated.
- Run any state-changing git command; the owner handles git.
- Install tools without asking.

## Verify

```
python3 -B -m unittest tests.test_build -v
node --test tests/viewer.test.js
```
